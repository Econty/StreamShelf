## Подробности и рекомендуемые исправления

### A-01. Учётные данные привязаны к текущей вкладке, а не к источнику задания

`Job` сохраняет `shared_ptr<Session>`, но не исходные tab ID, cookie store и документ. `Session::credentials()` берёт текущее `Session.tab`, отправляет его расширению и сохраняет запасной снимок только по URL. Проверка совпадения URL не различает аккаунты с одним адресом ресурса.

Сценарий: создать задание из Firefox Container A; пока оно ждёт очереди, выбрать вкладку Container B с тем же приватным URL и сделать ресурс доступным обнаружению. Запрос credentials для старого задания обращается к B. Результатом может быть файл другого пользователя. Сценарий не требует отправки cookies на посторонний домен; проблема в выборе аккаунта для одного домена.

**Доказательство:** статически прослежена цепочка `enqueue → Job.session → Session::credentials`; модельные проверки обеих реализаций расширения демонстрируют замену `account-A` на `account-B` для одного URI. Полная проверка с двумя реальными аккаунтами не проводилась.

**Исправление:** сохранять идентичность источника в Media/Job, передавать её при каждом запросе credentials и разделять кэш по профилю/store/tab/document/URL. При исчезновении источника явно требовать повторной авторизации или анализа.

### A-02. Повреждённый финальный файл блокирует повторную загрузку

В прямой HTTP-ветке `.part` переименовывается в `media.ext` до проверки FFprobe. Если проверка отклоняет содержимое, финальный файл остаётся. Следующий вызов сначала находит существующий `media.ext`, снова проверяет его и возвращает ту же ошибку, не переходя к HTTP-загрузке. `retryJob` сбрасывает флаги задания, но не это условие.

**Доказательство:** настоящий `App::download()` вызван дважды на локальном HTTP-ресурсе с контролируемым отклонением содержимого фиктивным FFprobe. Обе попытки завершаются ошибкой, финальный файл остаётся, сервер получает **один GET на две попытки**. Результат — `build/audit/app_retry/result.json`; цепочка кода — `src/app.cpp:1293–1302`, `:1397–1405`, `:1868–1878`. Проблема относится к прямой HTTP-ветке; не следует автоматически переносить вывод на все загрузки yt-dlp.

**Исправление:** проверять временный файл до присвоения финального имени. Различать доказанно неверное содержимое и невозможность проверки из-за отсутствия FFprobe/таймаута. При явном повторе позволять новый GET, сохраняя полезную копию отдельно.

### A-03. Выбранный профиль не определяет используемое окно браузера

`findBrowserWindow()` выбирает окно по EXE и размеру. При наличии окна `openExtensionsPage()` использует его и не вызывает запуск с аргументами выбранного профиля. При этом проверка `Preferences/extensions.json` работает с профилем, выбранным в приложении.

**Сценарий:** открыт профиль A; в мастере выбран B. Действия идут в A, проверка состояния — по B. Ограничение также отмечено в существующем `CHECKLIST.md`.

**Доказательство:** статический анализ `src/extension_installer.cpp:521–537`, `:772–787`, `:1677–1680`. Реальные профили пользователя не менялись.

**Исправление:** подтверждать профиль окна или запускать отдельное окно нужного профиля и привязывать весь мастер к нему. Идентификации по EXE недостаточно.

### B-01. Редактор метаданных и сборщик применяют разные модели правок

Отдельный экспорт вызывает `editedMetadataJson()`. Сборка контейнера читает исходный JSON и вручную применяет только несколько полей и `extraTags`; `metadataOverrides`, `metadataRemoved`, `metadataPathEdits` остаются без применения.

**Доказательство:** вызов настоящей `App::downloadAssembly()` с реальным FFmpeg: правка `genre: OLD → NEW` через `stageMetadataField()` даёт итоговый MKV с `GENRE=OLD`. Исходник не уничтожается; теряется смысл пользовательской правки в результате.

**Исправление:** использовать одну функцию применения всех правок перед экспортом и сборкой. Добавить проверки изменений, удалений и вложенных путей с последующим чтением результата.

### B-02. Внешние главы экспортируются без chapterEdits

Ветка встроенных глав использует `editedChapters()`, а внешние JSON/FFmetadata копируются или перечитываются из оригинала. Наличие `chaptersReady` и отредактированного списка не учитывается.

**Доказательство:** настоящий `App::downloadAssembly()` для форматов 0, 1 и 2 сохраняет `OLD`, хотя `chapterEdits` содержит `NEW`. Место: `src/assembly_download.cpp:240–258`.

**Исправление:** при подготовленных правках получать главы из `editedChapters()` независимо от происхождения файла; копировать оригинал только при отсутствии изменений.

### B-03. Сборщик возвращает исключённые главы

При обработке AV-источника сборщик сам задаёт `chapterInput`, если FFprobe увидел главы. Это происходит даже при отсутствии отдельного источника глав в выбранном составе. Позже `-map_chapters` копирует их в результат.

**Доказательство:** из контейнера с аудио и главой `PrivateChapter` выбрана только аудиодорожка. Созданный MKV всё равно содержит эту главу. Проверка выполнена через настоящий сборщик и FFprobe.

**Исправление:** разрешать перенос глав только при явно выбранном источнике глав; ожидания валидации строить из состава задания.

### B-04. Проверка disposition делает FLAC-экспорт необоснованно ошибочным

Для импортированной дорожки с `default=true` сборщик сравнивает флаги результата с исходными. FLAC не сохраняет такой флаг как контейнеры с несколькими дорожками; результат имеет `default=0`, и проверка объявляет ошибку.

**Доказательство:** реальная сборка аудио с `primary=true` в FLAC заканчивается сообщением «Контейнер изменил признаки дорожки…», хотя выходное аудио записано. Проверка находится в `src/assembly_download.cpp:625–629`. Перенос глав в FLAC отдельно проверен и сам по себе работает.

**Исправление:** учитывать возможности целевого контейнера ещё при планировании. Непредставимые флаги показывать как ограничение и проверять по заранее согласованному плану, вместо ошибки после кодирования.

### B-05. Доступность кодировщиков не обновляется вместе с FFmpeg

`detectVideoEncoders()` вызывается один раз из `start()`. Если FFmpeg отсутствовал, массивы остаются в состоянии «только копирование», а `videoEncodersReady` становится true. Установка компонентов и `refreshToolFiles()` обновляют версии, но не возможности. UI и `enqueueAssembly()` продолжают отклонять перекодирование.

**Доказательство:** изолированно выполнены настоящие методы приложения с фиктивным FFmpeg, объявляющим доступные кодировщики. До установки: `x264=0, ready=1`; после появления EXE и `refreshToolFiles()`: `x264=0, ready=1`; после явного `detectVideoEncoders()`: `x264=1, aac=1`. Результаты — `build/audit/app_retry/result.json`. Единственный рабочий вызов детектора в программе — `src/app.cpp:408`; детектор — `src/local_media.cpp:3–41`; ветки установки и обновления — `src/app.cpp:539–599`. Сценарий актуален для чистой установки компонентов в уже открытом приложении.

**Исправление:** после изменения FFmpeg пересчитывать полный снимок возможностей с номером поколения. Сбрасывать старые GPU-флаги и состояние ready, чтобы повторная проверка не сохраняла устаревшее true.

### B-06. Гонка при объявлении активной вкладки

`announce()` перед `await` запрашивает одну вкладку, а при отправке использует уже изменённый глобальный `tabId`. Получается согласованный по форме, но неверный по смыслу пакет.

**Доказательство:** VM-сценарий задерживает ответ A, переключает выбор на B и получает `{tabId:8,url:"https://a.test/watch",storeId:"account-A"}`. Воспроизведено в Chromium и Firefox.

**Исправление:** захватывать ID и номер выбора до ожидания, после каждого `await` проверять актуальность; аналогично защитить начало сканирования.

### B-07. Редирект теряет User-Agent и Referer

Рекурсивный `fetch()` получает пустой объект заголовков при любом редиректе. Вместе с чувствительным Authorization теряются и обычные заголовки, необходимые CDN и защите от хотлинкинга, в том числе внутри того же origin.

**Доказательство:** локальный HTTP-сервер требует заданные User-Agent/Referer. Прямой запрос проходит; переход 302 на том же хосте получает `HTTP 403`. На втором запросе сервер видит `StreamShelfNative/2.5` и отсутствие Referer. Проверялся настоящий `httpDownload()` из собранной библиотеки.

**Исправление:** определить отдельную политику переноса обычных заголовков и секретов, учитывать origin и переход HTTPS→HTTP. Cookies продолжать выбирать по домену и пути каждого адреса.

### B-08. Firefox не подключается при простой загрузке background

В Firefox подключение инициируют события установки, запуска профиля, alarm и ручное действие. В конце скрипта отсутствует первоначальный `connect(false)`, присутствующий в Chromium. Если фон загружен без этих событий и без ранее созданного alarm, автоматической попытки нет.

**Доказательство:** модель загрузки кода даёт 0 попыток Firefox против 1 Chromium. Сценарий disable/enable в настоящем Firefox **не проверялся**, поэтому его пользовательское проявление требует отдельной браузерной проверки. Семантика события запуска описана в [документации Mozilla runtime.onStartup](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/runtime/onStartup).

**Исправление:** инициировать безопасное фоновое подключение при загрузке контекста с последующими повторными попытками.

### B-09. После SPA-навигации наблюдатели продолжают работать

Обработчик URL-перехода меняет `scanning=false`, но не отправляет content script команду `stopDom`. При переходе без замены документа MutationObserver и PerformanceObserver остаются активными.

**Доказательство:** модельный сценарий обеих реализаций подтверждает отсутствие остановки. Background фильтрует устаревшие сообщения: утечка этих результатов в native-приложение не установлена. Подтверждён лишний обход страницы и внутренний обмен.

**Исправление:** единая процедура остановки сканирования для всех путей завершения, навигации, отключения и смены вкладки.

### B-10. Посторонний Firefox file picker принимается за установку XPI

Распознавание допускает браузерный `#32770` с кнопкой Open/Открыть. В `tickFirefox()` отсутствует обязательное ожидание диалога, открытого именно через установку дополнения, перед `navigateFolder()`.

**Сценарий:** при открытом мастере пользователь вызывает обычный Upload/Open на сайте. Мастер может заменить каталог этого диалога на папку XPI.

**Доказательство:** статическая цепочка `src/extension_installer.cpp:339`, `:398`, `:1225–1229` и `src/firefox_guide_state.hpp:32`. Живые диалоги не менялись.

**Исправление:** принимать picker только в ожидаемой стадии и с подтверждённым владельцем; сбрасывать ожидание после отмены.

### B-11. Старые файлы остаются в пакете и установленной программе

`Build.ps1` накладывает `cmake --install` на постоянный staging и удаляет только XPI двух конкретных версий. Inno Setup рекурсивно включает весь staging. Удалённые из проекта assets, старые DLL и необязательные tools могут продолжать распространяться. Например, DLL из предыдущего staging остаётся даже после явного исключения её из новой конфигурации.

Кроме того, установщик обновляет файлы поверх прежней установки и не задаёт правила очистки устаревших программных компонентов. Чистый staging сам по себе не удалит их у существующего пользователя.

**Доказательство:** статический анализ `scripts/Build.ps1:24–34`, `.iss:48`. Сам установщик не запускался.

**Исправление:** отдельный чистый staging и проверяемый манифест состава выпуска; управляемое удаление известных устаревших программных файлов при обновлении. Пользовательские данные учитывать отдельно.

### B-12. Срок жизни GL-текстуры короче срока жизни batch

`c.image()` записывает ID текстуры в batch, а рисование происходит позже в `c.render()`. При размере кэша 32 `previewTile()` немедленно удаляет первый элемент map. Он может уже использоваться ранее записанным batch того же кадра; новый GL-объект способен получить тот же ID.

**Доказательство:** статическая последовательность `src/ui.cpp:789–799`, `:496`, `src/render.cpp:148–151`, `:270–277`, `:319–328`. Визуальный GPU-сценарий не запускался. Кэш действительно ограничен; речь о времени удаления, а не о неограниченной утечке памяти.

**Исправление:** освобождать текстуры после завершения кадра и закреплять используемые этим кадром; применять LRU вместо выбора первого ключа map.

### C-01. Поздняя обложка не обновляет видео

`sent` хранит только MIME. Повтор с тем же URL и MIME подавляется, даже если появился poster или изменился title.

**Доказательство:** модельный сценарий video без poster → добавление poster: у видео остаётся пустой thumbnail, постер появляется отдельным изображением.

**Исправление:** сравнивать релевантные поля ресурса и обновлять карточку; включить нужные изменения атрибутов в наблюдение.

### C-02. Усилить интеграционные проверки

`tests/download_pipeline_tests.py` не зарегистрирован в CMake/CI. Он проверяет реальные инструменты, но вызывает их напрямую, поэтому не обнаруживает ошибки ветвления в App. Дополнительный режим `component_manager_tests --progress` также не входит в обычный CTest.

**Приоритет:** добавлять регрессии вместе с A/B-исправлениями: очередь из двух источников, повтор после плохого HTTP-ответа, редактирование глав/метаданных, чистая установка компонентов, редирект и смена вкладки. Для детерминированных сценариев использовать локальный HTTP fixture; отдельно иметь Windows job с реальными инструментами и изоляцией данных.

### C-03. Сохранять выбранные настройки

`saveSettings()` не сохраняет `fragments` и лимит параллельных задач. Они возвращаются к значениям 4 и 2 после перезапуска.

**Исправление:** сохранять значения с проверкой допустимого диапазона при чтении. Если настройка считается временной, объяснить это в интерфейсе.

### C-04. Упростить архитектуру наиболее сложных путей

`app.cpp`, `extension_installer.cpp`, `ui.cpp` содержат крупные обработчики с множеством состояний и очень длинными строками. Chromium/Firefox копируют почти одинаковую логику. Примеры уже найденных расхождений: подключение Firefox, применение правок метаданных в разных режимах.

**Исправление:** после функциональных исправлений выделить чистый план сборки, применение правок, состояние источника credentials и переходы мастера в небольшие модули. Общую логику расширений тестировать одинаковыми контрактными сценариями; браузерные различия оставить в адаптерах. Отдельно вычислять snapshot отфильтрованного списка медиа на кадр вместо повторного построения и сортировки.

### C-05. Проверять содержимое IncludeTools

Наличие `checksums.json` не подтверждает ни комплектность, ни SHA-256 EXE. Текущая программа не использует эти копии как установленные компоненты, поэтому риск ограничен упаковкой и происхождением дистрибутива.

**Исправление:** прочитать манифест, проверить каждый ожидаемый файл, его хэш и отсутствие лишних исполняемых файлов до копирования.

Браузеры и установленное приложение пользователя для интерактивных испытаний не менялись. Полный e2e с внешними сайтами, двумя реальными аккаунтами, окнами разных профилей и несколькими мониторами не проводился. Статические и VM-выводы нельзя выдавать за такую проверку.
